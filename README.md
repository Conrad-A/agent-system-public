# agent-system

A personal agent system for one host. A frontier **lead** directs, cheap
**workers** grind, a human **gate** decides what becomes durable.

- The **lead** is a Claude Code session opened in this repo. It plans,
  reviews and rules; it never does the grinding itself.
- The **workers** are DeepSeek V4.1 Flash (`deepseek-flash`), launched
  detached inside DeepSeek's own engine and reached only through
  `plumbing/` — do, status, steer, stop, resume. When the engine cannot
  start, a plain HTTP loop takes the job and says so in every place the run
  is visible.
- A **mechanical supervisor** rides every step — repeat, error loop, stall,
  context, budget — and trips before a worker can burn the day. Every filed
  report then goes up a **checker ladder**, R1–R5, where "not available" is
  never a pass.
- **Memory** is a git repo of files with provenance, two dates and a scope
  tag. Nothing enters it except through the human gate, and entries are
  superseded, never erased.
- A **nightly dream** re-reads a copy of memory and writes a diff of what it
  would change. It only proposes; it cannot touch the live files.

Nothing runs unless the owner starts it. That nightly pass is the single
exception, allowed precisely because it can only propose.

## The documents

- [`SPEC.md`](SPEC.md) — **canonical**: the whole design, complete enough to
  rebuild it 1:1. It wins every conflict.
- [`KICKOFF.md`](KICKOFF.md) — **to build it**: the replication prompt, one
  paste-ready block per host, each step with its flight test.
- [`agent-system-diagram.html`](agent-system-diagram.html) — **to see it**:
  one self-contained page with a single brief traced from `/worker` to a
  filed report. Generated by `plumbing/gen_diagram.py` — edit the generator,
  never the page.
- [`HANDOFF.md`](HANDOFF.md) — **the build record**: where things stand,
  what each flight test proved, what is still open.
- [`FIELD-NOTES.md`](FIELD-NOTES.md) — **the ground truth**: what the metal
  actually taught us on Fedora 44. A v1 document (it opens as a companion to
  `SPEC-v3.1.md`), carrying the v2 runtime notes added 2026-09-16.
- [`OPERATIONS.md`](OPERATIONS.md) — **daily use**: the command cheat sheet.
  Still the v1 sheet (2026-09-01); its v2 rewrite is the next doc job.

Also in the tree: `plumbing/` (the code — stdlib Python, the engine SDK its
only dependency, with a hermetic 64-test suite that makes no API calls),
`.claude/` (the hooks and the slash commands `/worker`, `/status`, `/steer`,
`/stop`, `/resume`, `/check`, `/swarm`, `/consolidate`, `/rotate`),
`memory/` (the gated files), `configs/stable.md` (every pin, with the date
it was recorded), `setup/` and `systemd/` (host install and the dream
timer), `MIGRATION.md` (v1 → v2, file by file), and the v1 record in
`SPEC-v3.1.md`, `HANDOFF-v1.md` and `docs/history/`.

## What you need

- Claude Code on a subscription — the lead.
- A DeepSeek API key — the workers.
- A search key for swarm mode: Parallel primary, Exa fallback. Optional
  until you run `/swarm`.
- `python3` ≥ 3.10 and git. No database, no framework, no daemon beyond the
  one systemd timer that runs the dream.
- A private git remote. This repo is the genome; the runtime body it writes
  — worker logs, reports, trajectories, events, costs, handoffs, dream
  diffs — lives outside the repo under `$AGENT_RUNTIME` and is never
  committed.

## Start

1. Clone the repo onto the host and open Claude Code in it.
2. Paste the block for your host from [`KICKOFF.md`](KICKOFF.md) as the
   first message. It builds the system one layer at a time and flight-tests
   each layer before the next.

## What is not in the kit

The public copy is the system, not its owner's instance: the owner-only
notes and the domain file are removed, the personal entries in `memory/`
are emptied to their headers (the system facts and the procedures stay),
and the runtime body was never in git at all. What you clone is the
design, the code and the discipline; the history is yours to make.
