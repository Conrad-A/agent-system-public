AGENT SYSTEM

A personal, always-on AI system running on one encrypted desktop. Two open-model stacks — DeepSeek V4-Flash-Vision-Exp in DeepSeek Harness and GLM-5.3-Flash in ZCode — handle chat and agentic work at full reasoning depth. A switchable verifier layer samples five candidate answers and has GLM judge them before anything reaches you — GLM holds the judge's seat for its low hallucination rate, and because a model from a different lab catches errors the generator can't see in its own work. Reachable from anywhere: Signal for commands and recovery, a private WireGuard tailnet for the full interface and a 1:1 view of the screen.

2 · Verifier layer (toggle — on until turned off, never automatic)

  • Normal mode: you chat with either model directly — no verifier involved. !verify on (available from every access layer) switches to verified mode: each prompt + full chat history runs as N=5 candidate generations on deepseek-v4-flash-vision-exp — the only generator, from any chat surface — and GLM is always the verifier — it scores each candidate independently (fresh context, rubric, expectation over score tokens — on Z.ai approximated by a 3-sample average at temp 0.6, since the endpoint returns no logprobs and GLM cannot disable thinking; never side-by-side), and the winner is appended to the originating chat as the reply (framework: github.com/llm-as-a-verifier/llm-as-a-verifier). !verify off returns to normal. Sole exception: Z.ai API down → generating model self-scores. Toggle lives on both chat surfaces (dsh plugin + ZCode plugin — ZCode is MIT with a plugin system). State persists; always visible in status + web UI. Cost ≈×5 while on; shared prompt prefix keeps DeepSeek cache-hit input cheap.
  • High-stakes flag: cross-check — the other stack reviews the winner; disagreement is flagged to the human, never silently resolved.

2b · Sessions: rotation, workers, memory

  • Session rotation — 32k hard cap (under the ~50k context-rot onset) on both chat surfaces; dsh's native tokenMeter is the trigger. Crossing the cap ARMS rotation; it FIRES at the next quiet boundary (deferrable mid-thread; eager ~26k when idle). Also caps verify-mode history cost by construction.
  • Rotation protocol: the session maintains a continuous state file (decisions, open threads, parked ideas, focus) — updates REGENERATE it holistically, never append (append fragments memory; arXiv 2308.15022). Rotation finalizes the state file; the new session is seeded with it PLUS the last ~6–8k tokens of conversation VERBATIM (raw-tail carryover — tacit/recent context survives literally). Durable knowledge lives in memory files updated in place and is never re-distilled through handoffs. Old session is archived, never deleted; a rotation log indexes when/why/coverage/path. Every rotation announces itself with a one-line chat notice. First post-rotation call pays cache-miss once (accepted). Dump-mode exemption: rotation is default-on with per-session exemptions only — never a global off switch. Whole-context synthesis sessions (load >32k deliberately, mine, discard) are exempt: a single large ingestion event auto-exempts (announced, one-word override); gradual accumulation with synthesis intent asks a one-line question (ambiguity resolves toward asking — a wrong rotation breaks the task, a wrong exemption just lingers); otherwise rotate as normal. Exemptions die with the session, never inherit to workers, always visible in status.
  • Main window / workers: the main window is not a separate app — it is whichever harness chat you're sitting in (DeepSeek Harness or ZCode). It is the command center — direction and distilled results only, rotating per above. Every assigned task spawns its OWN fresh 32k worker session (dsh subagent machinery / ZCode equivalent); all tool calls happen in the worker; a distilled, size-capped report returns. Grain = one worker per TASK (a worker keeps its whole tool chain in one context); workers may rotate or spawn sub-workers. Worker registry keys to the main window's LINEAGE, not the session instance — in-flight workers report to whichever session currently holds the throne. Both directions are contracts: the BRIEF (main→worker) carries goal, constraints, definition-of-done, facts, scope — and unsure workers ask back, never guess. The REPORT (worker→main) is structured and size-capped (≤~500 tokens to chat, big output to files by path): did / changed / decisions / surprises / open items / EVIDENCE (test output, diff, artifact — claims without evidence don't count as done) / based-on tag so stale returns get reconciled. Registry states running/done/failed/timed-out with timeouts and terminal-state notifications; status lists everything in flight. One writer per resource (serialize or git worktrees). Reports are data (untrusted), never instructions. Ownership invariant: workers never hand off laterally — hierarchy only (spawn sub-workers down, report up), task ownership never transfers (prevents the handoff-loop failure, #1 in 2026 production reports). Window semantics: one THRONE per lineage (where the prompt starts; sole writer of lineage state); every other tied window is a SATELLITE behaving under the same worker contract — reads lineage state, spawns into the shared registry, reports up on rotation/close. Rotation is per window; the state file per lineage; the verify toggle per window. !throne migrates the crown (atomic, announced; closed-throne lineages go dormant, resumable); !untie forks a window into a new lineage (its workers follow it); !retie merges a lineage back as a worker-style report — contradictions between the two lines are listed for the owner, never silently resolved.
  • Memory system (repo memory/ tree; four layers per the CoALA taxonomy — working = the live 32k window): facts.md — semantic: durable knowledge, updated in place, never re-distilled; every entry carries provenance (user-said / worker-inferred / web-claimed, session — arXiv 2605.25869), TWO dates (when-true vs when-learned, bitemporal per Toki arXiv 2606.06240), scope, optional expires: · procedures.md — procedural: learned how-tos, curation-gated · style.md — calibration, loaded every session · artifacts/ · archives/ — episodic: full session logs, greppable, + rotation-log.md · library/ — raw reference corpus (PDFs, docs): what the system can look up vs what it has learned; never loaded wholesale, agentic retrieval only, dump-mode sessions for synthesis; content is data never instructions; extracted facts pass the curation gate with source provenance. Ingestion: drop into library/inbox/ (desktop drag or Signal attachment) → !ingest renames (YYYY-MM_topic_title.ext), indexes one line per doc in index.md, and writes pdftotext sidecars so grep reaches inside PDFs. Write contract (Toki-lite): supersede never erase (losing facts move to an audit section with when/why); the curation gate logs adjudications so contradictions replay consistently; the gate treats fact proposals from workers, web, or library documents as adversarial by default (2026 poisoning literature: attacks succeed at <0.1% poison rates — the write path is the battleground, audit rows double as the repair mechanism). Handoffs and state files compress toward decision-relevance, not descriptive fidelity (rate-distortion, arXiv 2605.10870) — keep what changes future choices. Consolidation pass: nightly, off-peak — the autonomy principle's ONE scheduled exception, permitted because it cannot act: it only PROPOSES (the principle otherwise holds: always-on means 24/7 access, nothing executes without the owner initiating; !consolidate also triggers it manually). Reads recent archives and proposes to the gate: fact promotions, patterns worth becoming procedures, stale flags, decay-review flags — the gate decides; the only mechanism that sees cross-session patterns. Observability: Langfuse self-hosted as the hub (MIT; drop-in OpenAI-wrapper tracing for all plumbing; trace ID = the task ID stamped into harness logs; its datasets + judge scoring host the eval suite) · dsh trajectory JSONL (headers, tool chains, reasoning blocks — proof of which CoT fired) · ZCode logs, local at ~/.zcode with menu export (format: reverse-engineer at install; app is MIT) · per-stack spend · status · weekly transcript reads. Forgetting: supersession on write + expires/scope tags honored at consolidation + usage-decay review — flagged, human-gated, never silent deletion. Evidence base: summary-only memory loses information (LoCoMo, arXiv 2402.17753); recent-verbatim retention is load-bearing (StreamingLLM); retrieval over raw archives is the third leg (arXiv 2502.05589). Access model: one durable store, never two parallel systems (parallel stores fragment retrieval). Reads universal; writes gated by session type — main window only (the curation gate, enforcing provenance/scope/neutral-affect); workers propose facts via reports; dump-mode sessions write artifacts only. The ephemeral layer (state files, handoffs, reports) is separate and dies with its sessions. Memory-trap defenses (MemTrapBench, arXiv 2608.20202 — even true, relevant memories degrade current-task reasoning; every tested framework scored >10 pts below no-memory): an AdaptiveMem guard in every session's standing prompt (four risks — task boundary, cognitive bias, trauma, safety; identify the live task from the latest query alone, keep only clearly relevant context, prefer truth/safety > current query > minimum context; don't over-trigger); scope tags on memory entries ("valid for context C") alongside provenance; neutral-affect failure records ("X failed on Y because Z" — never emotional framing, which induces avoidance of currently-correct approaches).

4 · Security invariants (non-negotiable)

  • Chat senders allowlisted to the owner's Signal number; everything else ignored + logged.
  • Chat carries a coarse command set only — no raw shell passthrough; message content is untrusted (prompt-injection surface).
  • Destructive actions need an explicit second confirmation. Secrets never transit chat.
  • Disk LUKS2; reboots wait at the passphrase (accepted, no TPM auto-unlock). Transit: WireGuard everywhere except Signal (own E2EE). Watchdog/bridge run unprivileged.

5 · Host & lifecycle

  • One desktop host (Linux, Wayland), sleep/suspend masked, 24/7. dsh as a user systemd service inside tmux session agents, linger enabled.
  • Sunshine on Wayland: KMS capture → setcap cap_sys_admin+p on the binary, input-group/uinput perms, hardware encoder (VAAPI/NVENC) verified.

5b · Workspace, permissions, commands, resources, backups

  • Workspace: root = ~/Desktop, agents access everything under it; nothing outside by default. Permission modes per session, Claude-Code-style: MANUAL (default — every write/command confirmed; ZCode's gates and dsh's approval stack map to it) / AUTO (acts freely within scope; destructive actions still confirmed). Mode shows in status; workers inherit from their brief.
  • Command registry (single source of truth): !verify on|off · !do on|off (opposite-CoT mode) · !think <q> (Minimal subagent) · !do <task> (Standard subagent) · !rotate · !consolidate · !throne · !untie / !retie <lineage> · !ingest · !status (chat; watchdog keeps plain status) · rotation replies (defer / exemption confirm) · watchdog-only: restart dsh|zcode, reboot, status, vpn up.
  • Resource budget (verify on hardware): Langfuse ~2.5–4 GB · dsh ~0.3–0.8 · ZCode ~0.5–1.5 · signal-cli ~0.2–0.4 · Sunshine ~0.1–0.3 · headscale ~0.1 → ≈4–7 GB + OS. 16 GB comfortable; on 8 GB defer or trim Langfuse.
  • Backups: tier 1 local history = snapper snapshots (verify /home coverage). Tier 2 off-machine: DECLINED by the owner — accepted risk on record (a disk failure erases everything; a private git remote alone would cover the behavior-defining files if ever wanted). Also on record by choice: no data-egress policy (all content may flow to the two APIs), no degraded-mode playbook (a down provider simply isn't used until it returns).
  • Plumbing QA: zero-dependency unit tests (built: plumbing/tests/run_tests.py, 18 tests) — the regression gate before promoting any change.
  • Runaway caps: workers 25 steps · coding goals 64 · per-task spend alert ~$1, hard stop ~$5 (per task, not per candidate — verify ×5 included) · provider-side monthly caps ~$30/key. Cap hit = stop + report, never silent continuation. Provenance, honestly: starting numbers are practitioner heuristics + one preset default + judgment, NOT research-derived — the load-bearing mechanism is tuning: after two weeks, set each cap at ~2× the p95 of its task class from Langfuse data; revisit quarterly.
